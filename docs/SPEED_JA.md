# 保存速度の仕組み

更新：2026年11月7日。通信間隔の設定・8並列対応を含む実装。[旧版の実行ログと調査](PERFORMANCE_REVIEW_JA.md)、[大量保存と再開の使い方](BULK_DOWNLOAD_JA.md)を併せて参照。

## 通信方式と並行数

| 方式（秒数は既定値） | 全要求の開始間隔 | API | 媒体 |
|---|---:|---:|---:|
| 互換設定（CLI既定） | 2秒 | 2秒以上 | 2秒以上 |
| 通信分離（TUI既定）／CLI --balanced | 1秒 | 2秒以上 | 1秒以上 |

F10またはCLIの --intervalで共通・媒体間隔、--api-intervalでAPI間隔を変更できる。互換の共通間隔は最低2秒、通信分離では両方0.1〜3600秒。APIには共通間隔も適用するため、実効的な最小間隔は両設定値の大きい方になる。API間隔の既定値は2秒。これらはツール側の設定であり、提供側が公表した許容値ではない。

API・媒体の許可待ち、接続・ヘッダー待ち、本体転送中に状態管理のMutexを保持しない。APIが遅くても、別の媒体要求が設定上の間隔・同時数を満たせば進む。HTTPクライアントと接続プールは共有し、ネット同時数は合計8、APIはそのうち最大4。pximgのホスト名が違っても媒体の上限を増やさない。

並行数1〜8は固定ワーカーの数。本文準備・素材補完を交互に進め、集約コピーは別の上限付きキューで行う。並行数4が要求開始率4倍を意味するわけではない。

## 要求を減らす

小説の詳細JSONには本文が含まれる。表紙があれば通常さらに1要求、挿絵等は追加。同じURLの媒体は実行中の取得と検証済みキャッシュを共有し、各作品へ独立したファイルとしてコピーする。クエリを含む正確なURLを使い、ハッシュやサイズを再確認する。

共通表紙の合成小説4,000作品は作者一覧1＋本文4,000＋表紙1＝4,002模擬要求、固有表紙は8,001模擬要求で完了する。前者は旧経路の8,001要求から約半分になる条件であり、実際の作者の表紙重複率は未測定。実行中キャッシュは容量・エントリ数を制限するため、退避・削除された項目は再取得される場合がある。

画像の経路は詳細＋ページ情報＋各画像を維持する。1枚絵の追加API省略、HTTP/2・JSON圧縮、一般的な遠隔新版検出は今回導入していない。

## 待機時間と実測値

| last-run.json | 意味 |
|---|---|
| elapsed_seconds | ジョブの経過時間。実行記録自体の書き込みは除く |
| requests / request_budget | 開始した要求数／今回の有限予算。失敗・再試行も含む |
| rate_wait_seconds | 間隔による明示的待機の壁時間の重複を除いた集計 |
| transport_metrics.api / media | 要求数・bytes・平均要求率・ヘッダー／本体時間・失敗分類 |
| transport_metrics.admission_wait_seconds_sum | 複数ワーカーの許可待ち合計。壁時間を超え得る |
| transport_metrics.shared_media | キャッシュヒット・ミス・破損・退避・予約／保持bytes |
| stage_seconds | 本文準備・素材補完・集約の処理時間合計。ワーカー間で重なる |
| body_ready_count / full_complete_count | 利用可能な小説本文数／全素材が揃った作品数 |
| stop_reason | ユーザー取消・予算・HTTP拒否・ディスク等の停止理由 |

ヘッダー時間はDNS/TLS/TTFBも含み、別々に計測した接続時間ではない。p50/p95は最大2,048件の直近標本で、標本数・上限・総件数も記録する。要求率はジョブ開始後の平均で瞬間帯域とは異なる。これらは並行して進むため、経過時間から合計を引いて純粋な転送時間と解釈しない。

予算到達は新規要求の許可を止めるだけで、進行中の正常転送・検査・キャッシュコピーは確定できる。必要数ちょうどで予算を使い切っても、全件揃えば完了になる。媒体の一時失敗は追加最大2回だけ再試行する。拒否や404等の無期限再試行はしない。

## 保存I/Oと制約

原本の同期・原子的な確定・SHA-256・書き込み後の照合、うごイラ全メンバーCRC検査を維持する。小説本文を先に確定して素材補完を分けるため、ネット要求数の削減と同時に、本文を使い始めるまでの時間も改善する。

キャッシュ保持目標512MiB、取得予約1GiB、エントリ最大4,096。使用中の項目は固定されるため、保持中＋取得予約の合計上限は1.5GiBで、一時的に保持ファイルが512MiBを超える場合がある。原本／集約先の原子的コピー用一時領域と完成済み原本・コピーは、この数値に含まれない。コピーはワーカー数と集約キューで上限を持つ。ストレージの空き容量は他の処理でも変わるため完全な事前保証はせず、I/O失敗時に新規要求を停止して原本を保つ。

blocking HTTPの読み取り中は取消フラグでソケットを直ちに破棄できず、データ到着または要求全体の30秒期限まで待つことがある。接続は10秒期限。UIの取消表示が出る時間と、全通信の終了は分ける。

合成fixtureとループバックHTTPは、実サイト・TLS・Windows回線やストレージの性能を測るものではない。実サイトでの倍率・4000作品の完了時間は別途同条件での計測が必要。
