# 小説トップURLと、固定ID範囲の取得

`https://www.pixiv.net/novel` は小説のトップページで、全作品の一覧ではありません。今回、ログイン済みの新着APIに `lastId=100000` を指定すると、空の一覧と `lastId: null` が返りました。実際には2010年の公開・全年齢作品ID143が今も取得できるため、新着の終端を全期間の終端とは扱えません。

代わりに、開始時に新着画面などで確認した上限IDを固定し、1からそのIDまでを確認する機能を追加しました。保存できる公開・全年齢の本文だけを取得します。範囲内の存在しないID・取得不可作品も通信が必要です。上限より後に投稿された作品や、後から公開された作品の網羅は保証しません。処理したID数は、存在する作品数とは異なります。

## 初回の範囲指定

上限IDは明示指定です。次は、今回の新着画面で観測した最大IDを使用する例です。

取得せず範囲だけを設定する場合は `--prepare-only` を付けます。TUIの開始確認にも固定ID範囲を表示します。

```powershell
opixiv scan-novels "https://www.pixiv.net/novel" --last-id 29631368 --online --balanced --interval 0.01 --api-interval 0.01 --jobs 8 --request-budget 1000 --out "E:\Open-Pixiv-Downloader\archive\works"
```

本文は `E:\Open-Pixiv-Downloader\archive\works\novel\novel_<ID>.txt` に保存します。このコマンドは本文専用です。既存TXTとそのハッシュ、`novel-policy.json` の最小バイト数、過去の除外状態を再利用します。`--retry-unavailable` は受け付けず、意図した除外を復元しません。

`--first-id` は初回だけ指定でき、未指定なら1からです。一覧を数千万件分作る代わりに、最大1,000IDずつ処理します。IDがすべて保存・除外・取得不可などの確定状態になったバッチだけ、次のカーソルへ進みます。予算切れや途中失敗のバッチは同じ範囲を再確認し、保存済みの本文を再取得しません。

## 再開・TUI

```powershell
opixiv scan-novels --resume --online --balanced --interval 0.01 --api-interval 0.01 --jobs 8 --request-budget 1000000 --out "E:\Open-Pixiv-Downloader\archive\works"
```

初回に範囲を指定した後は、TUIでも同じ保存先・「本文のみTXT」を選び、`https://www.pixiv.net/novel` を単独で入力して Ctrl+S → Enter で再開できます。F5は固定範囲の確認、F11は最新の確認・保存がこのID走査に属するときに全体を再開します。途中で通常の作者・タグ・作品の保存を開始した場合、その後のF11はその通常の対象を優先します。

F10の並列数・要求間隔・要求予算が引き続き適用されます。TUIは作品ごとの行を数千万行ためず、集計とログで進捗を表示します。本文以外に必要な索引・カーソル・現在のバッチの管理情報は保持します。

1回の要求予算は1〜100万回で、到達したら停止します。alpha.18から **`--request-budget 0`** またはF10の要求予算 **0** で無制限にできます。無制限では固定範囲の終端までバッチをまたいで続行し、要求数だけでは停止しません。401・403・429、期待しない応答、保存失敗では停止し、拒否から自動的に再開しません。再開前に停止理由を確認してください。

## 範囲と管理情報

`novel-scan.json` が範囲・次のID・確定した集計・最後のバッチの結果を保持します。新規の範囲で上書きせず、再開時は保存した範囲を使います。現時点では保存先ごとに1つの固定範囲です。上限の自動更新・範囲拡張は行いません。

約2,963万IDの範囲では、既存177万件余りの再利用を考慮しても数千万回の照会が必要です。前回のタグ取得速度をそのまま使った終了予想は確定値ではありません。範囲走査の実測、空き容量、取得不可の割合を確認して見積もります。
