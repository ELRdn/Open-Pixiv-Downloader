# 検証記録

検証日：2026年10月29日（日本時間）
対象：Pixiv Archive Lab 0.1.0a1
実行環境：Linux / CPython 3.12.14
検証対象：新規実装と合成fixture。実在の作品・アカウントは使用していない。

HTTPテストは応答を模擬しており、pixivへネットワークアクセスしていない。

## CLIの通し確認

同梱fixtureの`user:9001`を使って、CLIを別プロセスとして順番に実行した。

| 操作 | 結果 |
|---|---|
| `plan` | 4作品を発見、選択。fixture API呼出1回 |
| 初回`fetch` | イラスト・漫画・うごイラ・小説の4作品がcomplete。fixture内のAPI/媒体参照16回 |
| `verify` | 4作品中4作品でバイト数・SHA-256一致 |
| `pack` | completeの4作品をZIP出力 |
| 2回目`fetch` | 4作品を完成済みと確認。作者一覧のfixture API呼出1回だけ。本文・媒体の再取得0回 |

テストの呼出回数はネットワーク実測値や速度ベンチマークではない。

## 追加レビューで解消した問題

- 一時ファイルの予測可能な名前を、ランダムな同一ディレクトリ内ファイルに変更した。
- 応答中断の`IncompleteRead`を正常な失敗状態へ変換した。
- `NaN`・無限大の待機時間を入力段階で拒否した。
- JSON内の欠損・型変更、壊れたmanifestの復旧処理を確認した。
- 除外作品が件数上限の先頭を占有しても、後続の未試行作品へ進めるようにした。
- 作品IDがリクエストと違う応答を保存成功にしない。

## 検証していないこと

- 現在のpixiv実サイトでの取得成功、匿名で取得できる範囲、ログインが必要な対象。
- サービス側のレート制限値、処理速度、大規模取得の安定性。
- Windows・macOS・モバイルでの動作。
- 公式小説パーサとの全入力同値性。
- GIF/MP4/EPUBへの変換、シリーズの統合閲覧UI。
- 作品改訂の検出・版保持、削除の監視、総容量の制御。
- 最新利用規約の全文。調査環境では公式規約ページを取得できなかった。

`complete`は本alphaの対応範囲での保存契約、`verify`は保存ファイルとmanifestの整合性を示す。元サイトの最新版、全投稿の網羅、著作権・利用許可、内容の真正性を保証するものではない。
