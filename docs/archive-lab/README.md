# Pixiv Archive Lab

**公開情報の解析と独立実装による、ローカル作品アーカイブの検証用alphaです。**

調査日：2026-10-29（日本時間） / バージョン：0.1.0a1 / Python 3.11以上 / 実行時の追加依存なし。

イラスト・漫画・うごイラ・小説を扱う取得アダプターと保存エンジンを実装しています。**検証済みなのは合成fixture上の動作です。実際のpixiv作品のオンライン取得、ログイン状態での取得、全件互換性は未検証です。** 完成版として宣伝しないでください。

pixiv、pix-web-DL、Powerful Pixiv Downloaderの公式製品ではありません。

## インストール不要のオフライン実演

ZIPを展開し、このREADMEと同じフォルダで以下を実行します。Windowsでは`python`、環境によっては`python3`を使用します。

```bash
python run.py plan user:9001 --fixture examples/synthetic-fixture.json --out demo-archive
python run.py fetch user:9001 --fixture examples/synthetic-fixture.json --out demo-archive
python run.py verify demo-archive
python run.py pack demo-archive demo-export.zip
```

4形式の合成作品を保存します。実在の投稿は収録していません。小説は`demo-archive/works/novel_1004/index.html`をブラウザで開いて読めます。

同じ`fetch`をもう一度実行すると、ファイルのハッシュが一致する完成済み作品をスキップします。作者一覧を読むfixture API呼び出しは行いますが、完成済み作品の本文・媒体は再取得しません。

```bash
python run_tests.py
python examples/make_fixture.py
```

後者はテスト用画像・ZIP・応答JSONを標準ライブラリだけで再生成します。

## 現在の実装範囲

| 項目 | alphaで実装していること | 制約 |
|---|---|---|
| 入力 | 作者、単体作品、小説シリーズのID/正規URL | 検索・ランキング・ブックマーク取得なし |
| 静止画 | 返却された原寸URLをページ順に保存 | 実サイトの互換性は未実測 |
| 漫画・複数枚イラスト | ページ数と詳細情報の一致を確認 | ページ抜けは失敗として記録 |
| うごイラ | 元のフレームZIPと表示時間JSON | GIF/MP4等への変換・再生UIなし |
| 小説 | 元本文、平文、HTML、表紙、挿絵、メタデータ | EPUB・縦書き切替・シリーズ統合本なし |
| 小説記法 | 章、改ページ、ルビ、リンク、太字、斜体、傍点、挿絵 | 公式パーサとの全入力互換は未検証 |
| 挿絵 | 直接アップロードと、可視性を確認できた作品参照 | 未承認・取得不能の参照は欠損として残す |
| 再開 | 完成済み作品をSHA-256検証してスキップ | 未完了ファイルは再取得。バイト位置からの再開なし |
| 再実行 | 新規・未試行のIDを優先し、過去の失敗で前進を妨げない | 完成済み作品の編集・削除の監視なし |
| 監査 | SQLite台帳、作品manifest、catalog.jsonl、実行履歴 | ハッシュは真正性や権利を証明しない |
| ZIP | 完成済み作品のみをZIP64対応で出力 | 分割ZIPや容量による自動分割なし |

「complete」は、**このalphaが対象とする作品本文・媒体の保存契約が成立したこと**です。コメント、閲覧数の推移、いいね履歴、アカウント情報等まで保存した意味ではありません。

## オンライン経路について

実装された通信経路は**匿名で取得でき、一般向けで公開と確認できる作品のみ**を対象にします。Cookie・パスワード・トークンを受け取る機能はありません。ログインが必要な公開作品は、このalphaでは取得できない可能性があります。

`--online`を付けた時だけ実ネットワークへ接続します。以下の`123456`は**書式説明用の数字**です。自身の作品など、保存対象として選んだ正しいIDへ置き換えてください。

```bash
python run.py plan user:123456 --online --out my-archive --types novel --limit 10
python run.py fetch user:123456 --online --out my-archive --types novel --limit 10
```

`plan`も作者・シリーズの列挙には通信を使います。本文や画像の取得はしません。個別の取得可能性は`fetch`時に判定します。認証の必要性、削除・公開設定の変更、取得中の作品追加などにより、列挙と保存数が一致しない場合があります。

通信は直列で、リクエスト開始間隔は最低2秒、既定は1実行500リクエスト、1ファイル256MiB、1実行100作品です。これは実装上の暫定値で、pixivが許可・保証した値ではありません。作品数上限は1000、要求予算は5000までに制限しています。総ディスク使用量の上限は未実装です。

401・403・429、リダイレクト、HTMLチャレンジはジョブを停止します。制限を回避する処理はありません。502・503・504は最大2回の再試行で打ち切ります。サーバーが長い`Retry-After`を指定した場合も停止します。後で続行するときは保存済みの状態を再利用します。

一般向けか不明・非公開・取得不能の作品は、完了件数と別に記録します。前回の`skipped`・`unavailable`を再確認する場合だけ`--retry-unavailable`を指定します。`failed`・`partial`・`paused`は再試行候補ですが、未試行の作品を先に処理します。

## 出力の読み方

| パス | 内容 |
|---|---|
| `state.sqlite3` | 作品ごとの状態 |
| `last-run.json` | 最後の実行結果、発見数・選択数・未着手数・除外数 |
| `runs/*.json` | 各回の実行結果 |
| `catalog.jsonl` | 保存状態と正規化メタデータ。本文データセットではない |
| `works/art_ID/images/0000.ext` | ページ番号0始まり・4桁以上で保存する原画像 |
| `works/art_ID/frames.zip` / `frames.json` | うごイラ素材と時間情報 |
| `works/novel_ID/source.txt` | pixiv記法入り本文。改変せずUTF-8で保存 |
| `works/novel_ID/plain.txt` | 検索・読み上げ向けの派生平文 |
| `works/novel_ID/index.html` | 相対画像参照を使うオフライン閲覧用HTML |
| `works/*/raw.json` | 公開・一般向け確認後のAPI本文スナップショット |
| `works/*/metadata.json` | 作者・出典・取得時刻・シリーズ情報等 |
| `works/*/manifest.json` | ファイル一覧・SHA-256・バイト数・欠損理由 |

状態は`in_progress`、`complete`、`partial`、`paused`、`failed`、`unavailable`、`skipped`を区別します。`fetch`の終了コードは全選択範囲が完了なら0、一部完了や中断理由があれば1、引数・環境エラーなら2、Ctrl+Cは130です。除外作品がある実行は、見た目の成功件数が増えても`partial`として報告します。

`verify`は保存後のバイト数とハッシュを検査します。元サイトの最新版、作品の真正性、利用許可の検証ではありません。`pack`は失敗・部分保存・取得不可の作品を収録しません。

同じ出力先への同時実行はロックします。異常終了で`.run.lock`が残った場合は、その出力先を使うプロセスが止まっていることを確認してからロックファイルを削除してください。

## OSS公開前の残作業

1. 自分の作品・許諾済みの作品を使い、実サイトで4形式と挿絵・シリーズ順を確認する。
2. 通常のブラウザセッションをローカルで使う拡張アダプターを設計し、認証情報をログ・ZIP・外部サーバーへ流さない。
3. 実レスポンスを匿名化した契約テストを追加し、API変更を検出する。
4. Windows・macOS・Linuxで実行、パス、ロック、長いファイル名を確認する。
5. 版管理・更新検出・総容量上限・ユーザー向けGUIを、必要な順に追加する。
6. 公開直前の利用規約、依存ライセンス、READMEの機能表示を再確認する。

今回、公式規約本文は調査環境から取得できませんでした。この資料は現行の全自動取得を許可・禁止と法的に判定したものではありません。公式の[対策説明](https://inside.pixiv.blog/2023/05/09/183635)は、API制限・認証によるデータ制限・大量取得への対処を説明しています。

ソフトウェアの公開条件と、保存する作品の利用条件は別です。MITライセンスはこの独立実装に適用し、第三者の作品へ利用許可を付与しません。メタデータの`ai_training_permission`と`redistribution_permission`は、根拠を確認していない限り`unknown`を保持します。
