# ツールの更新通知

0.2.0-alpha.3から、引数なしのTUI起動時に、GitHubのmainブランチにあるCargo.tomlをバックグラウンドで取得する。`package.name` が本ツールと一致することを確認し、`package.version` を現在の実行ファイルのバージョンと比較する。

新しい版があれば、ロゴの下に「アップデートが利用できます！」と新バージョンを表示する。バージョン番号はSemVerで比較するため、alpha.9とalpha.10、正式版と開発版を文字列順で誤判定しない。ビルドメタデータだけの違いを更新とは扱わない。バージョンを上げていないコミットは通知の対象外。

## 操作

- F8、またはロゴ下の確認ボタン：最新版を再確認。直前の確認から最低1分空ける。
- F9、または更新方法ボタン：現在の版、確認できた版、更新手順を表示。
- 更新画面でEnter：保存処理が動いていなければ終了し、通常のターミナルにコピー用コマンドを出す。保存中は終了させない。
- 更新画面でEsc：元の操作へ戻る。

PowerShellで、次の1行を実行する。現在のツールを終了してから行う。

```powershell
cargo install --git https://github.com/ELRdn/Open-Pixiv-Downloader.git --branch main --locked --force
```

作業フォルダーへの移動やgit pullをせずに、同じ取得元から最新版をビルド・インストールできる。完了後は `opixiv` で起動する。この操作にはRustのビルド環境とGitが必要。

## 通信と失敗時の動作

確認先は固定の `https://raw.githubusercontent.com/ELRdn/Open-Pixiv-Downloader/main/Cargo.toml`。接続タイムアウト3秒、全体5秒、応答上限64 KiB。リダイレクトは追跡しない。取得した内容からインストール用コマンドを組み立てず、更新コマンドもコード内の固定値を使う。TLSの証明書・ホスト名検証を有効にし、OSの信頼済み証明書ストアを使う。

起動後は保存処理のないタイミングで1時間ごとに確認する。応答待ちでURL入力や保存処理をブロックしない。通信失敗・不正なTOML・別の製品名・不正なバージョンは「確認不可」とし、最新版と判定しない。すでに新しい版の存在を確認した後の一時的な通信失敗では、その通知を保持する。

自動確認を止める場合は `opixiv --no-update-check` または環境変数 `OPIXIV_NO_UPDATE_CHECK=1`。この場合もF8による明示的な手動確認は可能。引数付きCLIのplan / fetch / verify / collect / packでは確認しない。合成デモの保存は通信しないが、通常のTUI起動時の更新確認は別の通信である。

## 検証範囲

ローカルHTTP応答による正常系・403・リダイレクト、不正な応答、バージョン比較、通知を受けても入力を続けられること、保存中に更新画面のEnterで終了しないこと、表示幅とクリック操作をテストした。Linux実PTYで実際のGitHub確認とF9経由の終了・コマンド表示も確認した。Windows実機の表示と更新コマンドの実行は未確認。

開発時は、通知対象の更新でCargo.tomlとCargo.lockのバージョンを更新する。通知されるかの判定は公開後のmainと実行ファイルの版に依存する。
