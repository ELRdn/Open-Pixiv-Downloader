# 画像・小説の集約

0.2.0-alpha.4から、作品別のアーカイブに加え、読む・見るためのファイルを次の2フォルダーへ集約する。保存先がarchiveの場合の対応は次のとおり。

| 作品別のファイル | 集約先 |
|---|---|
| `works/art_130117333/images/0000.jpg` | `works/image/art_130117333_p0000.jpg` |
| `works/art_130117333/images/0001.jpg` | `works/image/art_130117333_p0001.jpg` |
| `works/novel_29500410/plain.txt` | `works/novel/novel_29500410.txt` |
| `works/art_1003/frames.zip` | `works/image/art_1003_ugoira.zip` |
| `works/art_1003/frames.json` | `works/image/art_1003_frames.json` |

画像は原本の形式を維持する。小説本文は元のplain.txtのバイト列をコピーする。小説の表紙・挿絵・HTML、取得応答、作品のmetadata・manifestは集約しない。うごイラのZIPには表示時間が含まれないため、時間情報のJSONも一緒に集約する。GIFなどへの変換は行わない。

## 作成と操作

fetchでは作品保存後に自動で集約する。保存済みと判定してダウンロードを省略する作品も、その入力対象について集約先を確認する。planでは集約しない。

過去の保存済み作品すべてを集約する場合は、TUIで保存先を指定してF4→Enter、または `opixiv collect 保存先` を使う。旧Python版で保存したアーカイブにも対応し、通信や認証情報を必要としない。集約対象はSQLiteにcompleteまたはpartialとして記録され、manifestに対象ファイルがある作品である。partialの小説は、本文自体が正常なら本文を集約できる。

Alt+IとAlt+N、または画面下の画像・小説ボタンでフォルダーを開く。F4画面でもI・Nで開ける。F4の画面は↑↓でスクロールできる。実行中の処理がある場合は集約処理を重ねて開始しない。

## 独立したコピーと衝突

ハードリンクやシンボリックリンクを使わずコピーする。集約先の編集が作品別の原本に波及しない。ディスク容量はコピーしたファイル分増える。

作成時はストリームでSHA-256とサイズを照合し、一時ファイルから確定する。読み込みエラー、内容の不一致、中断では一時ファイルを破棄する。集約先がすでに存在する場合、manifestのハッシュ・サイズと同じ内容なら再利用し、異なる内容なら上書きしない。コピー中に別のファイルが作成された場合もno-clobberで保護する。

集約先で編集したファイル、または同名の別ファイルがある場合はF3に問題を表示する。必要に応じてそのファイルの名前を変えるか別の場所へ移し、再集約する。集約フォルダーで削除したファイルは、元の保存物が正常なら再作成できる。ファイルの自動削除や、既存の集約ファイルの自動置換は行わない。

## 検査と結果

結果は `collection-report.json`、fetchの結果内の `collection`、TUIのF3に記録する。コピー数、既存ファイル数、問題、作成元と集約先の対応を確認できる。元の作品保存が完了していても集約に問題があれば、fetch全体はpartialを返す。SQLiteの原本保存状態はcompleteのまま維持する。

`opixiv verify` は作品別のmanifestに記録されたファイルを検査する。集約先の編集によって原本の検査が失敗することはない。集約先の状態を再確認する操作はcollectである。ZIP出力は従来どおり検査済みの作品別ファイルから作り、集約フォルダーの複製を重ねて含めない。
