# Rust + Ratatuiへの移行

2026年10月31日。利用者の指定により、主実装をRustへ変更した。RustがPythonを子プロセスで呼ぶ構成ではなく、URL解析、通信、列挙、保存、SQLite、検査、ZIP、小説変換をRustで実行する。Python版は互換性検証の基準として残している。

## 実装と互換性

| 層 | 現行実装 | 引き継いだ契約 |
|---|---|---|
| TUI | Ratatui + Crossterm | URL一括入力、保存先、並行数、対象一覧、結果・欠損の詳細、検査、ZIP、停止 |
| 引数付きCLI | clap | plan / fetch / verify / pack、JSON結果、終了コード0・1・2・130 |
| 保存 | rusqlite（SQLite同梱）、tempfile、SHA-256 | state.sqlite3、works/、schema_version 1のmanifest、catalog.jsonl、実行記録 |
| 通信 | reqwest blocking + rustls | 匿名、HTTPSの送信先制限、共有間隔・予算、拒否応答時の全体停止 |
| スケジューラー | 標準スレッド + channel | 最大1〜4作品。停止後は補充せず、実行中処理を回収 |
| 小説 | Rustの括弧対応トークナイザー | 原文保持、構造をHTML化、未知記法・未保存画像を表示、外部素材の自動読み込みなし |

主な意図的な差：並行数の既定値を2へ統一し、自動通信リトライを行わない。旧CLIの `interactive` は `tui` の別名として受け付ける。旧Pythonパッケージから `opixiv` エントリーポイントを外し、Rustの実行名にした。以前インストールされたPythonランチャーは更新操作なしには消えないため、READMEに起動パスの確認方法を記載している。

うごイラはZIP内の全メンバーをEOFまで読み、CRCを検証する。展開して保存せず、展開後サイズを各256 MiB・合計1 GiBに制限する。合成CRC破損を完了にしないテストを追加した。画像・フレームのデコーダー検査や、表示時間を原素材と比較する受入は別に必要。

## 実測したこと

- Rustテスト25件。4形式、原文・小説構造、欠損、画像破損の修復、排他ロック、CRC不一致、URL・パス検証、列挙の重複除去、選択上限、再開。
- ローカルTCP通信で、共有要求間隔と予算、302・401・403・429の停止ラッチ、HTML素材の拒否を検証。外部サイトを使っていない。
- 素材転送を待ち合わせる障害注入で、実際の2作品の重なりと、拒否後に後続作品を開始しないことを確認。
- `tools/check_rust_compat.py` で、Rust保存→Python検査・再開・ZIPと、Python保存→Rust検査・再開・ZIPを実行。原本バイト列・ファイル一覧を照合し、破損修復後に旧版でも検査できることを確認。
- 旧Pythonテスト49件、Rustのfmt・Clippyを実行。
- Linuxの実PTYで、120桁×36行の起動、F2でデモ、Ctrl+Sで確認、Enterで4作品保存、Alt+Vで4作品検査、Alt+EでZIP出力、Escで正常終了。
- TestBackendでは24×8、40×18、80×24、120×36、160×45の描画と、NO_COLOR・確認画面を検証。

起動画面画像は実PTY出力を端末エミュレーターで読み、セル単位に描画したもの。Windowsのスクリーンショットではない。

## 残る受入

Windows実機での新規導入、PowerShell・Windows Terminalの描画、IME・貼り付け・キー入力、終了後の端末復元、日本語パスでの保存を確認する。GitHub ActionsにはWindows／Linuxのビルドと同じオフライン受入を配置したが、実機での操作とは区別する。

実サイト・通常セッション・全小説記法の照合は未完了。匿名かつ公開・全年齢と確認できる作品に限定する現行契約は、本人が閲覧できる全範囲の実装を意味しない。更新検出と旧版保持も未実装である。Rust化だけで通信速度の改善を実証したとは扱わない。

ロゴは本プロジェクト用に定義した文字パターンで、`█` の面と二重罫線の影を描き分ける。Hermesのロゴやアート、架空の機能一覧は含まない。
